Payroll/HCM App v1.1.21 — Code Review Notes

BASELINE
Built directly from Payroll/HCM App v1.1.20. Existing stored payroll data remains under the same localStorage key and is migrated in place.

RESIGNATION / FIXED-TERM JOB DATA FIX
- Added reconciliation between saved Job Data rows and the employee's current employment segment before payroll calculation.
- A saved current-employment Termination row is now authoritative for the employment end date and termination reason.
- If an old Expiry of Fixed Term row has been deleted and replaced by an earlier Voluntary Resignation, stale or duplicate current employment segments are collapsed and the resignation boundary is used.
- Regular Pay is generated only for scheduled working days before a normal/manual termination effective date. A Voluntary Resignation remains an exclusive boundary, consistent with the existing app rule that the termination effective date is the first non-employed day.
- Automatic fixed-term expiry processing now checks for an explicit saved Job Data termination and will not recreate an Expiry of Fixed Term event over a resignation.
- The reconciliation runs for both whole-pay calculation and employee-selected Calculate Pay, so cached/stale employment segment data cannot continue paying a full fortnight after a saved resignation.

TARGETED REPORTED SCENARIO
Regression coverage recreates a fixed-term employee with stale expiry/open employment-segment data, removes the expiry from saved Job Data, and stores a Voluntary Resignation effective 25/05/2026. For the PPE 04/06/2026 cycle, only Friday 22/05/2026 is payable at 7.5 hours. The test verifies:
- Regular Pay = 7.5 hours, not 75 hours;
- termination date = 25/05/2026;
- termination reason = Voluntary Resignation;
- duplicate/open current segments are removed;
- no pay is generated on or after 25/05/2026; and
- automatic fixed-term processing does not recreate an expiry event.

UNCHANGED
- The v1.1.20 cumulative retro settlement fix remains in place.
- Terminated employees can still receive legitimate Additional Earnings without recreating post-termination Regular Pay.
- Annual Leave Loading and payslip grouping behaviour are unchanged.
- Casual-payment and concurrent-position workflows remain unchanged as requested.
