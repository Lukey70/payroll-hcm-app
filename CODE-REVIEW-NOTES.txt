Payroll/HCM App v1.2.1 review

Shared renderers: Payroll Management and self-service call the same Job Summary and calendar functions. MSS mounts the existing Additional Earnings renderer with a scoped employee list. Its original hidden payroll editor is cleared to prevent duplicate DOM IDs; leaving the portal resets the mounted scope.

MSS period saves stage rows, recheck manager scope, employee and cycle after the delay, validate each row through SelfService, then delete absent rows only in that employee/period. State and persistence roll back on error. Failed saves never show success. Rate-based source rows keep an empty amount override; fixed/amount earnings preserve engine semantics. HDA must exceed substantive pay; overpayment adjustments remain current-period-only.

Multiple managers: active acting plus substantive reporting assignments, multiple reporting values and eligible position occupants resolve to a unique recipient list. Sequential superseded assignments do not accumulate permissions. Current routing controls request visibility, detail/payment scope and reminder recipients. Actual approval actor is frozen on decision; repeated decisions fail.

Operations Manager: active position identity/name and current effective job assignment determine the exception. New own ESS requests approve automatically after normal validation. No missing-manager error or pending reminder is generated for those approved requests.

Payroll approver labels: new payroll bookings carry source and approver metadata; legacy source-less payroll bookings display Payroll. ESS/MSS sources and actual decision actors remain distinguishable after export/import.

ESS payslips combine scoped current payResults with historical payslips. Open pay is viewable. Export controls are disabled and handlers recheck finalisation. The existing payslip renderer retains finalised-only disbursements.

Hours use the same engine booking validator as Payroll Management. UI resets/partial constraints follow payroll rules. Request submission continues using pending reservations in a cloned validation state.

Version/cache metadata v1.2.1; storage key unchanged. Full existing regressions plus payment and integrated self-service DOM/event tests pass. Exact delivered archive is re-extracted and retested. No live-browser or real-data acceptance QA is claimed.

Material limits unchanged: browser-local storage, browser-readable credentials, no server-side authorization, no shared multi-device database, no closed-app notifications.
