Payroll/HCM App v1.1.32 — Code Review Notes

Baseline
- Built from verified v1.1.31.
- Existing effective-dated payroll, retro, LSL, deductions, leave, casual-employment and finalised-history logic was preserved unless directly affected by a v1.1.32 request.

Observed implementation changes
- Added loginCredentials to state migration/export/import, defaulting missing employee passwords to 1234.
- Login eligibility is derived from active employees; terminated employees are excluded.
- Position access is derived from the latest effective saved non-termination Job Data position, with a current pay-rate/name fallback for legacy data lacking a position number.
- Landing areas are Payroll Management (position flag), ESS (active employee), and MSS (position flag). ESS/MSS are not yet implemented beyond Coming Soon.
- Home preserves the authenticated session and returns to the landing page.
- Leave earnings rows now carry leaveBookingId/bookingStartDate/bookingEndDate metadata for presentation consolidation without changing scheduled paid units.
- Payslip display consolidates one leave booking where treatment is homogeneous; rate/position differences remain distinct.
- Casual Job Data saves zero hoursByDay and bypasses non-casual schedule validation.
- Denied leave is excluded at the shared absenceCalendarStatus source, covering both calendar reports.
- Current-period Casual Earnings rows use a shared payslip grouping key so different selected positions do not create multiple payslips solely for Casual Earnings.

Compatibility / risk notes
- Existing finalised payslips are not mutated to add leave booking IDs. The new consolidated leave-range behavior is strongest for newly calculated/current rows that carry booking identity metadata.
- Position access flags were introduced before this release. v1.1.32 enforces them at the landing page. Administrators should ensure at least one active user's current position has Payroll Management access before deployment.
- Client-side passwords are intentionally demo-only and should not be represented as production security.
