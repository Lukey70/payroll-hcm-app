Payroll/HCM App v1.1.37 — Code Review Notes

Scope reviewed for this release
- Real Job Data save path for temporary acting movements and Higher Duties Allowance.
- Upgrade migration of v1.1.36 acting pay-rate rows saved with the wrong change type.
- Substantive-rate lookup used by Higher Duties Allowance.
- Retro Casual Earnings routing/settlement when cycle metadata is stale.
- Future non-casual contracts and historical casual earnings.

Findings / implemented corrections
1. v1.1.36's UI save path created every non-termination Job Data pay-rate row with changeType='Permanent'. For Acting Higher Level this caused activePermanentPayRate() to select the acting rate itself as the normal/substantive rate, making the HDA differential zero. v1.1.37 saves acting movement rate rows as Temporary, repairs existing linked rows on migration, and defensively excludes acting-linked rows from substantive-rate lookup.
2. The v1.1.36 retro Casual Earnings regression used a correctly stored historical cycleId, so it did not cover saved/imported states where the Casual Earnings work date was historical but cycleId still pointed at the open pay. v1.1.37 routes Additional Earnings by source date when dates are present and aligns Casual Earnings cycleId during migration. The retro engine therefore sees the historical earning in the correct finalised source cycle.
3. Future-dated non-casual Job Data remains isolated from the historical casual source position/rate and does not suppress the retro payment.
4. Existing cumulative retro settlement remains authoritative, so already-finalised Casual Earnings retro is not recreated.
