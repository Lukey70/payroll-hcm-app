Payroll/HCM App v1.1.19 — Code Review Notes

BASELINE
Built directly from Payroll/HCM App v1.1.18 without resetting or replacing stored payroll data.

TERMINATED EMPLOYEE ADDITIONAL EARNINGS
- Removed the calculation short-circuit that excluded an employee entirely when they were no longer employed during the selected pay cycle.
- Ordinary pay, leave and public-holiday generation still requires the employee to be employed on the relevant date.
- Saved Additional Earnings can still be processed for a terminated employee when entered for the selected pay period.
- This does not recreate Regular Pay after termination.
- Existing payout/correction and retro rules remain intact.

ANNUAL LEAVE LOADING PAYSLIP GROUPING
- Annual Leave Loading now uses the underlying/base pay rate for payslip grouping.
- This keeps current Annual Leave Loading on the same payslip as Annual Leave and Regular Pay for the same position/base rate.
- The loading remains its own earnings line and retains its own 17.5% calculated rate/amount.
- Different positions or genuine base-rate differences still generate separate payslips where appropriate.
- Existing display consolidation of multi-day Annual Leave and Annual Leave Loading remains unchanged.

UNCHANGED BY REQUEST
- Casual payments have not been added to Additional Earnings.
- Concurrent/multiple-position employment has not been redesigned.

See test-results.txt for syntax, regression, static package and browser smoke-test results.
