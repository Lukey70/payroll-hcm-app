Payroll/HCM App v1.1.30 — Code Review Notes

- Source base: verified v1.1.29 release.
- Payroll calculation remains in payroll-engine.js; browser/report presentation remains in app.js; persistence/migration remains in data-store.js.
- `Annual Leave Overuse Recovery` is a label-only rename; existing full-deficit resignation recovery logic is preserved.
- Retro comparison now explicitly recognises direct-dollar Additional Earnings (Overpayment Adjustment, Reimbursement, Travel Allowance and Bonus) as amount-only. Retro rows for those descriptions carry amountOnly=true with units/rate zero, avoiding the previous fallback to baseRate-derived Units/Rate.
- Leave Status is stored on the leave booking. Payroll calculations use only Approved bookings; Absence Calendar may still display non-approved bookings with its existing pending marker semantics.
- Saving a Termination Job Data row calls the termination/leave conflict helper after employment reconciliation. Any booking extending into the termination effective date or later is retained, set to Awaiting Manager Approval, status-history stamped and notified once per employee/effective date.
- Position Data now persists `accessManagerSelfService` and `accessPayrollManagement`; migration defaults missing legacy values to false. No access enforcement is activated yet because ESS/MSS/role identity is not implemented.
- Full Node regression suite and all four JavaScript syntax checks pass before packaging.
- Real Chromium DOM rendering was attempted over a successful local HTTP 200 response but timed out; no browser pass is claimed.
