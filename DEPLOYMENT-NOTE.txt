Payroll/HCM App v1.1.30

DEPLOYMENT
Upload all application files in this folder together. Before replacing an existing version, use Export Data and retain the JSON backup. v1.1.30 preserves the existing payrollAppData/localStorage schema and migrates saved data through DataStore.migrate().

IMPORTANT UPGRADE BEHAVIOUR
- Existing leave bookings default to Approved if they do not already contain a status; a statusHistory array is added safely when missing.
- Existing positions receive Access to Manager Self Service = false and Access to Payroll Management = false when those fields are absent.
- Existing finalised payslips are not rewritten. Amount-based retro presentation is a display/calculation-row refinement for current/future retro processing.
- Existing LSL reconciliation markers/history are preserved and the v1.1.26 one-time reconciliation does not rerun merely because v1.1.30 is opened.

MAJOR CHANGES
- Annual Leave recovery label renamed to Annual Leave Overuse Recovery.
- Retro amount-based Additional Earnings show no Units/Rate, including Retro PFY.
- Leave Status can be Approved, Awaiting Manager Approval or Denied; pending/denied leave is not processed through payroll until Approved.
- Saving a termination flags affected future leave, changes it to Awaiting Manager Approval and creates a notification.
- Position Data adds future access-control flags for Manager Self Service and Payroll Management.

PAYROLL CONTROLS PRESERVED
- Persisted currentCycleId remains the authoritative open pay.
- Original anchor remains PPE 04/06/2026, period 22/05/2026–04/06/2026.
- Retro cut-off remains 03/05/2026.
- Finalisation remains manual.

TESTING
See test-results.txt and RELEASE-NOTES-v1.1.30.txt for actual automated/static/browser-attempt results and known limitations.

This remains a client-side payroll demonstration and is not production payroll software.
